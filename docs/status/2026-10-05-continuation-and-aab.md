## Recovery behavior implemented

A separate scheduling controller continues the existing inventory with explicit
resume in the same job. It shares one total budget, backs off worker timeouts to
an explicit cap, and reserves the remaining scheduling time for finalization
once every source bundle is sealed. Pass and no-progress limits prevent endless
retry. Source/checkpoint integrity errors and non-timeout worker/finalizer errors
are terminal. An incomplete finalized catalog is not changed into success.

History records approved pass metrics outside the private media workspace. Raw
objects, typetrees, media, font files, private logs and keys are not included.
Every pass retains the existing integrity checks; cursor counts are only retry
liveness observations. Recipe compatibility is preserved rather than invalidating
all previous decoded objects to change scheduling.

The historical source observation is in `2026-10-05-continuation-baseline.json`:
run `37308162343` processed 192 of 222 original bundles before a timeout/budget
boundary. This increment's 222-bundle test is an explicitly authored corpus,
not a claim that those original pending bundles have been recovered.
