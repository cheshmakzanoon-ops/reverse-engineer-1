# Verified item-system increment — 2026-10-03

Base: `4718351689aafcd553d45a2e24564c06b2435825`, single `main`.

## Repaired behavior

A real Area3D overlap previously produced zero grants. The boxes had no
body-entered connection and did not watch the kart collision layer. Their
"held" state belonged to the box, not a kart; every roll used the same
constant random value and the player table, including for AI. Triple boosts
and normal shields were misclassified by name prefixes. Collection could
immediately trigger a boost instead of granting an independently usable item.

Now actual contact atomically claims a box only for an eligible kart with an
empty slot. Each kart owns its inventory, charges, equip/re-equip clock and
per-race pickup limits/cooldowns. Boxes respawn independently; overlapping
full inventories, rivals, disabled controls and non-karts cannot steal or
duplicate a claim. A seeded RNG advances reproducibly, positive weights are
normalized, and AI/player tables remain distinct. The original tables are
not rewritten or filtered to hide unsupported behavior.

The keyboard/gamepad/touch item command reaches the same per-kart executor.
Boosts use the usable's duration, acceleration ratio and speed offset;
triple boosts are three separate activations. One-hit shields, duration-based
super shields, dropped hazards, ricocheting and homing projectiles, a
leader-seeking projectile model, satellite delay, spinouts, braking,
invulnerability and recovery state have functioning port-side implementations.
HUD text shows the held count, shield/spinout/wrong-way state and any rejected
effect. AI uses recovered attempt intervals and probabilities. The E key is
mapped to item use; touch already provides an item button.

## Exact scope and limitations

Recovered: spots, box/table ids, weights, counts, durations, boost values,
shield-hit count, projectile speeds/lifetimes and hit-effect parameters.
**PORT-SIDE approximations:** distance-band selection, integer equip times
interpreted as milliseconds, RNG algorithm, collider radii, initial boost
impulse, ground-following projectiles, homing/ricochet logic, spin braking,
recovery dropping an item, and capped-pickup rejection leaving the box intact.
Super-shield turning modifiers, native throw/glide/bounce-tracking behavior,
culture-pod flight/attachment phases and satellite distance-specific effects
are not implemented as native equivalents. Original visuals, animation, VFX
and audio are still absent. Debug boxes/spheres and text are not final art.

No APK/AAB was produced locally: Android SDK/export templates remain absent.
No emulator or physical device was tested. The preceding remote runtime job
was still queued when checked; local passing tests do not imply a CI result.
No recovered data, original DMG or LFS object was modified.

Next dependency: a reproducible Android build plus pause/restart/menu/save
navigation, then authorized original-content import and device acceptance.
