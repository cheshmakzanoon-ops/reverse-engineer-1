## Implemented and exercised

- Each kart owns a `KartCommand`. Only `PlayerDriver` reads global player
  actions. `KartAI` writes only its own command; stopping an AI cannot release
  the player's accelerator. Kart calls its driver immediately before physics.
- Multi-touch throttle/brake/steer/drift/reset/item state uses finger ownership,
  analog steering and matching drawn/hit-test regions. Cancellation, focus
  loss, resizing, pause and disabling clear held state. Brake precedence restores
  the accelerator when brake is released. Item/reset are one-shot requests;
  item gameplay is NOT implemented by this input change.
- Selected player and AI handling profiles and +Z-facing grid transforms are
  assigned before `_ready`. HUD is bound to the actual player/director.
- Steering rotates velocity by yaw delta, not the entire accumulated heading.
  Forward throttle opposes reverse motion. Countdown/finished-kart input is
  locked. Reset restores both position and orientation and clears temporary
  motion/drift/boost state.
- Drift charge pays the highest earned tier once on release, not every frame.
- AI uses spatial segment projection rather than integer-truncated speed*dt.
